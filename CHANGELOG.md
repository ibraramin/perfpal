### Fixed
- **`PERF-RS-LOOP-003` `for`-header false positive (+ the matching `is_innermost`/`statement_role` inconsistency)** (plan `rust-backend` R4; found by dogfooding, completed after review): the Rust backend set `loop_depth` **before** visiting a `for_expression`'s iterable (`value` field), so the one-time iterable expression in `for c in text.chars()` was treated as per-iteration body work and filed `LOOP-003` (char-wise processing *inside a loop*) — contradicting `docs/heuristics/rust-catalog.md` §3, which states such headers correctly never fire. Unlike C's per-iteration increment/condition, Rust's `for` iterable is evaluated **once**. Fix in `src/scanner/backends/tree_sitter_rust/mod.rs`: `enter_loop` visits the iterable at the **outer** depth and skips it in the body walk (new `visit_children_except`), and a new `in_for_iterable(node)` guard makes `meta_for` force `is_innermost = false` and `call_position` return `(StatementRole::Unknown, false)` for iterable nodes — without which an event reports the self-contradictory `in_loop_depth = 0` **and** `is_innermost = true`, and `is_innermost`-keyed rules (RS-LOOP-004) still false-fire on `for i in 0..(n / d)`. `while`/`loop` conditions and bodies keep the inner (per-iteration) depth (the `while let` condition contract is unchanged). Six backend tests lock it (`for_iterable_is_outside_loop_body_depth`, `charwise_call_in_loop_body_stays_in_loop`, `for_iterable_call_does_not_shadow_body_depth`, `for_iterable_arithmetic_is_not_innermost`, `while_inside_for_iterable_stays_in_loop`, `loop_in_for_iterable_does_not_demote_body_innermost`) — the last two complete the class: the exclusion stops at the **nearest loop of any kind** (so a `while`/`loop` nested in the iterable stays in-loop), and `is_innermost_event` now skips the iterable when checking whether the `for` nests a loop (fixing a pre-existing FN where a loop *inside* the iterable demoted the `for` body's events from `is_innermost`). Effect: the bare-`for`-header probe drops from 1 finding to 0; the self-scan drops **6 findings, 0 added** (1225 → 1219) — all once-evaluated iterable events: 2× `LOOP-003` (`charts/mod.rs:133`, `reporter/mod.rs:731`), 3× `STR-002` (`.len()` in a `for` iterable: `graph.rs:127`, `scanner/mod.rs:469`, `scanner/mod.rs:573`), 1× `LOOP-008` (chain in a `for` iterable: `resolver/mod.rs:1545`); `LOOP-003` no longer misfires on `src/`, and the `examples-rust/` corpus still fires `LOOP-003` on the intended body-primary shape (23/23 intact). Deferred as tracked follow-ups (not fixed): `LOOP-004` fires on float division and `LOOP-007` on a `BTreeMap` index — both need IR/tier support beyond the syntactic tier and are recorded in `docs/evidence/dogfood-rust-backend.md` §1.3.
