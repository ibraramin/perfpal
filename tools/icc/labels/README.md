# Blind manual-label packets

These packets are generated by `tools/icc/make_labels.py`. They contain **no
Perfpal field values**. The annotator should not open
`site_comparison.json` (it is the non-blind answer key used only by
`compute_icc.py`).

## Files

| file | blind? | purpose |
|---|---|---|
| `loop_packet.json` | yes | 100 loop-bearing functions with numbered source |
| `site_packet.json` | yes | 100 call-site candidates inside loop bodies |
| `site_comparison.json` | **no** | Perfpal `resource_sites` reference for scoring |
| `loop_labels.json` | - | annotator output (must be created) |
| `site_labels.json` | - | annotator output (must be created) |

## Loop annotation

Open `loop_packet.json`. For each item, read the numbered function source and
label the function's loop metrics manually:

```json
{
  "labels": [
    {"id": "loop-001", "loop_count": 1, "loop_body_loc": 4, "max_loop_depth": 1}
  ]
}
```

* `loop_count`: number of syntactic loops (`for`/`while`/`do-while`; Python
  comprehensions count generators as loops; Rust `loop` counts).
* `loop_body_loc`: number of distinct source lines in the union of all loop
  body spans. Use the body only, not the loop header. For a braced body the
  convention includes the brace lines, matching Perfpal and the reference
  tools.
* `max_loop_depth`: maximum syntactic loop nesting.

Save as `labels/loop_labels.json`. Use the packet `id` verbatim.

## Site annotation

Open `site_packet.json`. Each item is a call-like candidate inside a loop body.
The `candidate` / `column` fields identify which call on a line is meant when a
line contains more than one call. `column` is a **0-based byte offset** into
the source line (matching `metrics.json` `resource_sites[].column`). Label:

```json
{
  "labels": [
    {"id": "site-001", "is_alloc": true, "is_external_io": false, "cfg_gated_c": null}
  ]
}
```

* `is_alloc`: the call allocates heap memory (e.g. `malloc`, `calloc`,
  `realloc`, `strdup`, `new`, collection construction/append-to-new).
* `is_external_io`: the call performs external I/O (file, socket, console,
  network, process, database).
* `cfg_gated_c`: **C only**. `true` if the call is inside a preprocessor branch
  that is disabled/conditionally disabled (`#if 0` or equivalent); `false` if
  it is in live code; `null` for non-C items.

Save as `labels/site_labels.json`. Use the packet `id` verbatim.

## Scoring (implemented in `compute_icc.py`)

* Manual loop metrics: ICC(2,1) against Perfpal for `loop_count` and
  `loop_body_loc`, plus exact agreement for `max_loop_depth`. Gate: pooled
  `loop_body_loc` ICC >= 0.75.
* Manual sites: Perfpal is the prediction and the manual labels are truth.
  Each binary field gets a confusion matrix (TP/FP/FN/TN), precision/recall,
  Cohen's kappa and ICC(2,1); gates require kappa and ICC >= 0.70. Raw
  agreement is descriptive only. The frozen prereg rule 4 drops
  `io_sites_in_loops` after the blind audit (recall 0.55); `io_site_count` is
  descriptive. Perfpal emits `resource_sites` for every language: allocation
  sites for C/Rust and external-I/O sites for all five. Comparison entries are
  matched to packet items by `(path, line, 0-based column)`, so two calls on
  the same line are scored independently; an entry with no matching in-loop
  Perfpal site is `neither`. Only `cfg_gated` is C-specific (`null` for
  non-C).

If either label file is absent, the manual gates are reported as
`manual labels pending` and do not fail the run; the independent-parser gates
still apply.

## Known packet limitation

`tools/icc/extra/dead.c` contains only four call-like sites inside its two loop
bodies (two live: `printf`, `malloc`; two under `#if 0`: `printf`, `malloc`).
The packet therefore includes all four rather than the requested ten; the
remaining 96 items come from the 200-function sample. The two `#if 0` sites
still exercise `cfg_gated_c = true` and the live sites exercise `false`.
