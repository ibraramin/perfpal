Appendix A. Heuristic reference

rule_idtitledescription
PERF-PY-ALLOC-001Loop-invariant construction inside loopDetects a container/object constructor (list/dict/set/tuple/str/bytes/open/DataFrame/Series/array/ndarray) called inside a loop with only literal (or no) arguments — a loop-invariant value rebuilt each pass; f-string-in-loop is NOT a finding (98–99.6% of raw C hits were f-strings).
PERF-PY-ALLOC-003Superlinear list accumulation in loopDetects non-in-place `acc = acc + [...]` concatenation of a list-bound name reassigned inside the loop, and append/extend onto a list-bound receiver NOT rebuilt inside any enclosing loop (the accumulator carried across iterations) — CPython rebuilds and copies the list each pass (O(n²)). Silent when the receiver is reset inside the loop (the benign CTL-APPEND-LOCAL control). Flagship.
PERF-PY-ALLOC-004Eager iterable materialisation inside loopDetects `list()`/`dict()`/`set()`/`tuple()` with a non-literal iterable argument inside a loop — forces an eager O(n) allocation and copy, defeating lazy iteration.
PERF-PY-ARCH-001Import cycleDetects cycles among RESOLVED internal Python import edges (via break_cycles); unresolved internal imports stay data-only with no finding. Info, conservative — thresholds are not decision-grade on Python.
PERF-PY-ARCH-002Hot componentRanks directories by aggregated cyclomatic complexity and reports only the hottest component above a conservative floor. Info — thresholds are not measured on Python in W0 (measured in W4).
PERF-PY-ARCH-003Cross-file call couplingDetects name-based cross-file call edges (a callee name with exactly one other-file definition); LOW confidence because Python duck typing makes name coupling noisy.
PERF-PY-ASYNC-001Blocking call inside `async def`Detects `time.sleep`, blocking HTTP clients (requests/httpx/urllib), synchronous DB driver methods and `open` inside an `async def` — the blocking call stalls the single event-loop thread. The `async def` gate is required (166 production blocking calls in sync functions vs 0 real hits).
PERF-PY-ASYNC-002`await` inside a loopDetects an `await` whose event metadata reports `in_loop_depth ≥ 1` (additive AwaitEvent stream) — sequential awaits serialise latency that `asyncio.gather` could overlap.
PERF-PY-CALL-001Direct recursionDetects a function body containing a direct call to its own name; framed as CPython call cost and `RecursionError` depth, not C stack cost.
PERF-PY-CALL-002High cyclomatic complexityDetects branch-count complexity above threshold (default ≥ 15), reported per function.
PERF-PY-COMPREHENSION-001Manual loop collapsible to a comprehensionDetects a loop whose body is a single `list.append` statement (single-statement gate) appending to a list-bound receiver — a list comprehension compiles to a specialised `LIST_APPEND` with inline iteration.
PERF-PY-EXECUTOR-001Executor/event-loop creation per iterationDetects `ThreadPoolExecutor(...)`, `ProcessPoolExecutor(...)` and `asyncio.new_event_loop()` constructed inside a loop — worker/selector setup is re-paid every iteration and never amortises.
PERF-PY-LOOP-001Deep loop nestingDetects loop nesting depth exactly 3 (one finding per maximal nest entry) — an O(n^k) candidate zone under interpreted iteration.
PERF-PY-LOOP-002Expensive I/O call inside loopDetects file/network/subprocess/socket I/O inside a loop — direct I/O names, network-rooted methods, and filehandle read/write methods. `print`/`input` are deliberately excluded (72–83% of the C rule's raw hits were logging). The message splits hoistable handle setup (open/urlopen/Popen/...) from element-wise streaming transfer (batching is the candidate); evidence carries io_kind.
PERF-PY-LOOP-003`range(len(seq))` iterationDetects `range(len(seq))` inside a loop (the `len()` gate keeps it false-positive-free) — prefer direct iteration or `enumerate`.
PERF-PY-LOOP-007Linear index scan of a list inside loopDetects (a) membership `x in list` / `x not in list` where the container is a list-bound name (additive `ComparisonEvent.operator`), and (b) a list-bound name subscripted by an enclosing loop's induction variable — including a lone `seq[i]` and deeper `seq[i].field` chains. The kind gate excludes set/dict (kills the CTL-IN-SET false-positive class). Flagship.
PERF-PY-LOOP-009`try`/`except` inside a loopDetects a `try_statement` whose event metadata reports `in_loop_depth ≥ 1` (additive TryEvent stream) — CPython sets up per-iteration exception handling. Honest that the zero-cost-`try` claim is version-dependent (CPython ≥ 3.11). Info.
PERF-PY-MEM-002Container copy inside loopDetects `copy`/`deepcopy` (module function or `.copy()` method) inside a loop — a whole new container is materialised per iteration (`deepcopy` also walks the graph with a memo dict).
PERF-PY-N1-001DB/HTTP call inside loop (N+1)Detects a DB/HTTP round-trip per iteration (receiver-root and call-name family gated) — the N+1 pattern; batch into `IN (...)`, a JOIN, or a bulk request. Flagship.
PERF-PY-PANDAS-001Row-wise pandas iterationDetects `iterrows`/`itertuples` or `apply(axis=1)` (receiver-root gated) — pandas materialises a Python object per row, dwarfing the vectorised work. Info; frequency caveat (4 hits on the W0 corpora).
PERF-PY-PANDAS-002`concat`/`append` in loopDetects `pd.concat`/`DataFrame.append` inside a loop — the whole frame is copied per iteration (O(n²)). `.append` is syntactically indistinguishable from `list.append`, so the receiver must be a proven DataFrame. Info; 0 hits on the W0 corpora.
PERF-PY-STR-001String accumulation in loopDetects string accumulation across iterations on a `str`-bound identifier inside a loop: both the explicit `s = s + piece` form and the in-place `s += piece` form (additive augmented-assignment BinaryOpEvent). Gated on the name being reassigned within the loop (accumulation, not a loop-invariant read) — CPython strings are immutable, so each pass allocates and copies (O(n²)); `str.join` is the fix.
