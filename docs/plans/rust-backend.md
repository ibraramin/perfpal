## Idea
Add a Rust language backend to Perfpal so it can analyze Rust code — and run on its own codebase (dogfooding). This is the milestone that precedes the 0.2.0-beta.1 release. ADR-0001 already made the architecture language-agnostic (parser-agnostic IR keyed (path,name,span), one scanner backend per language, triers syntactic→semantic→dynamic), and modules.md §5.2 prices language additions: rule_id is an OPEN PATTERN and scan.languages / files[].language widen as a MINOR schema bump — no major bump. Research verdict (librarian, session 23): official `tree-sitter-rust =0.24.2` (tree-sitter org, MIT, ABI LANGUAGE_VERSION 15) is compatible with our pinned `tree-sitter =0.26.13` (accepts ABI 13–15), exposed as a `LANGUAGE` constant exactly like tree-sitter-c 0.24.2, so the backend glue is symmetric. Scope (founder): FULL catalog mirrored — every heuristic family implemented for Rust with PERF-RS-* rule ids (mapping the C catalog's intent to Rust idioms), not a subset. Key grammar facts to design around: functions are flat `function_item` nodes (direct name/parameters/return_type/body fields — no declarator unwinding); parameters are `parameter` nodes with pattern+type fields and receivers are positional `self_parameter`s; loops are `for_expression`/`while_expression`/`loop_expression`; `impl_item`/`trait_item` bodies carry the hot method `function_item`s; `use_declaration`/`mod_item` replace include semantics for ARCH-*; `struct_item` fields come from `field_declaration_list`/`ordered_field_declaration_list`; `index_expression` has NO fields (positional children, unlike C's subscript_expression); comments are `line_comment`/`block_comment` with no `comment` supertype; attributes are SIBLING `attribute_item`/`inner_attribute_item` nodes that must be skipped/consumed when walking items. Rust's conditional compilation differs from C: plain `#[cfg(...)]` is a normal attribute whose annotated item remains a structured sibling (so the C guarded-content bug does NOT recur), but `cfg_if!` and `macro_rules!` bodies are opaque `token_tree`s — the plan must decide/document whether heuristics cover macro-generated items (recommended: document the blind spot, do not re-parse token trees in this milestone). Also plan a Rust-specific IR additive field only where genuinely needed (e.g. method receiver / trait context), versions stay additive/minor, and the semantic resolver (libclang) does not apply to Rust — the Rust backend is syntactic-tier only in this milestone. Finally: dogfood — run the built tool over Perfpal's own source tree, publish the report as evidence, and add an examples-rust corpus; bump the crate version to 0.2.0 in preparation for the beta. Dual review + full gates before commit.

## Implementation
- R0 research + grammar pin: add `tree-sitter-rust =0.24.2` (exact pin, MIT, ABI 15) + `tree-sitter-language 0.1`; verify the pinned pair link-tests (parser.set_language on a minimal .rs TU, zero ERROR nodes) exactly like the tree-sitter-c ABI test; record the grammar pin + node-kind mapping + cfg/attribute rules + token_tree blind spot in a backend doc (docs/architecture/rust-backend.md) and cite modules.md §5.2 as the sanctioned extension point (no new ADR needed unless the IR contract itself changes).
- R1 scanner backend: new `src/scanner/backends/tree_sitter_rust/` implementing the same `Extraction` interface (file records, includes→use/mod edges, globals→static/const items, structs→struct/enum items, macros→macro_definition/macro_invocation events, functions→function_item + impl/trait methods); extension-based language dispatch (.rs → rust, .c/.h → c) in the scanner; FileRecord.language = "rust"; ParseHealth capture with the same ERROR/missing semantics; skip/consume attribute_item siblings when walking items.
- R2 IR + schema MINOR bump 1.1→1.2: widen scan.languages to ["c","rust"] and files[].language (the rule_id pattern is already open); add any Rust-only IR fields ADDITIVELY (serde default) only where a heuristic provably needs them (e.g. receiver/trait context); re-emit docs/schema/metrics.schema.v1.2.json + embedded byte-copy + drift test; regenerate the golden report tree; keep v1.1 docs as history.
- R3 heuristics: implement the full catalog for Rust with PERF-RS-* rule ids, mirroring each C family's intent to Rust idioms — e.g. alloc/churn (Vec clone/reserve/Box/Rc in loops), string building (String + format!/push_str in loops vs capacity), loops (nesting depth, I/O or expensive setup in loops, char-wise string work, variable-divisor arithmetic), recursion/complexity, memory/sizeof analogues (struct layout/padding via field_declaration_list, large-struct-by-value), membership scans, pointer/lifetime-chain depth analogues, and architecture (module use-graph cycles/fan-out/deep chains, hot components, cross-module call coupling). Registry stays true ascending rule_id (declaration order load-bearing). Document per-rule Rust mapping + accepted FP classes + the macro token_tree blind spot in docs/heuristics/catalog-v1.md (or a rust-catalog companion).
- R4 dogfood + corpus: run the built binary over Perfpal's own source tree; publish the generated report as evidence and triage the findings (real issues fixed vs accepted FP classes documented); add an examples-rust corpus mirroring examples/ density and silent controls; verify all PERF-RS-* rules fire against real tool output and record counts.
- R5 tests + gates + version: parser-free IR fixtures for every PERF-RS-* rule and their negatives/suppressions, a guaranteed-guarded-content lock for Rust (attribute_item sibling handling) and a real-parse fixture lock (per LL-009: pair parser-free fixtures with real-parse locks over the dominant input shape), end-to-end scan→analyze over a mixed C+Rust tree, and golden/determinism regen. Run fmt --check, clippy -D warnings --all-targets, cargo test, and the semantic-clang feature build. Bump crate version 0.1.0 → 0.2.0 (pre-beta). Dual review (@reviewer + @requirements-reviewer) + fix wave, then commit.
- R6 docs + close-out: update README (supported languages, PERF-RS-* table), modules.md §4.2/§5.2 (second backend landed), catalog companion, CHANGELOG, lessons-learned if warranted; EOL ritual (state/handoff/activeContext); hand off to plan `beta-release`.
