## Idea
Execute evidence-beta M3 (plan `evidence-beta`): add a Python language tier to Perfpal with `PERF-PY-*` rule ids, honest reframing to Python idioms, minimal binding/alias inference, and a schema MINOR bump 1.2 -> 1.3 admitting the "python" language token. This plan tracks the multi-session work (the M3 step is one line in evidence-beta; this is its execution plan, mirroring how `rust-backend` tracked the Rust tier's R0-R6). Grammar = official `tree-sitter-python = "=0.25.0"` (MIT, ABI 15, compatible with the pinned tree-sitter 0.26.13 runtime window 13-15), exact-pinned per ADR-0001 G5. The `semantic-clang` resolver tier stays C-only; Python is `resolver_tier = syntactic` throughout.

Founder-locked decisions (this planning session, after an @oracle pressure-test):
- STRATEGY: Python's "deep tier" is AST + lightweight binding/alias inference, NOT bytecode and NOT native C-extension analysis. Bytecode requires CPython at analysis time (breaks the single-binary/zero-runtime-dep model), opcodes are version-adaptive (PEP 659), and real bottlenecks are invisible in bytecode; it belongs to the runtime-profile-ingestion pillar (CONFIRMED-1, T3), not the static analyzer. Native C-extension analysis is low-coverage for AI Python repos (the C is usually pip-installed, not in-repo). Tier model to state honestly: T1 = static AST + binding awareness (THIS plan / M3) -> T2 = cross-module resolver (post-M3 plan `python-resolver`) -> T3 = runtime profile ingestion (CONFIRMED-1).
- RULE SET: retire 10 C/Rust rules that are not honest Python transfers, keep ~13 mirrors + Python-native additions. RETIRE: TYPE-001 (no by-value structs), TYPE-002 (no struct padding), MEM-001 (no sizeof), ALLOC-002 (no free), STR-002 (len() is O(1)), STR-003 (memory-safe), LOOP-004 (interpreter-bound; drop the bytecode-era div/mod premise), LOOP-005 (global store = dict write), LOOP-006 (every Python call is dynamic dispatch), LOOP-008 (attribute chains idiomatic + PEP 659-cached). KEEP/REFRAME: ALLOC-001 (heavy per-iteration object construction of loop-invariant shape), ALLOC-003 (superlinear growth -- flagship), STR-001 (`str +=` in loop; MEDIUM, honest about CPython refcount==1 amortisation), LOOP-001, LOOP-002 (expanded I/O families), LOOP-003 (range(len(seq))/index iteration -> enumerate), LOOP-007 (membership/index scan -- flagship), CALL-001 (RecursionError framing), CALL-002, ARCH-001/002/003, MEM-002 (container copy/deepcopy in loop, info).
- NATIVE ADDITIONS (Python-specific; mechanism-cited): pandas `df.iterrows()`/`apply(axis=1)`; `pd.concat`/`DataFrame.append` in loop; N+1 DB/HTTP in loop (e.g. Django `.objects.filter` chain inside a loop); `list()`/`dict()` materialisation churn; `range(len(x))`; BLOCKING CALL inside `async def` (`requests`/`time.sleep`/DB) -- highest-value native rule; sequential `await` in loop; executor/event-loop creation per iteration; manual comprehension loops. CUT/DEMOTE: import-in-loop (cut), exception-driven control flow (Info only), `re.compile`-outside-loop (CUT -- CPython's 512-entry re cache makes it folklore).
- INFERENCE: minimal binding/alias inference ships IN this plan (not deferred): per-file import-alias map (`import pandas as pd`, `from pandas import DataFrame as DF`), per-function single-assignment local kind lattice (list|dict|set|str|bytes|DataFrame|Series|ndarray|filehandle|unknown), parameter annotations, call-receiver root, `async` flag on FunctionRecord. Additive serde-default IR fields only (existing pattern); confidence MEDIUM where inference is used; do NOT claim `semantic` (the central upgrade gate reverts unbacked claims).
- IMPORT GRAPH: best-effort resolution (relative imports + scan-root packages to real files); unresolved internal imports stay DATA-only with NO finding (mirrors the Rust N1 decision that killed the unresolved-edge FP stream). `__init__.py` re-export hub handling decided explicitly.
- ENGINE: tree-sitter-python stays (revised in W1 only if f-string/comprehension span fidelity proves painful; `rustpython-parser` is the noted alternative -- published, MIT, typed AST).
- CORPUS: `examples-python/` is a real PACKAGE (`__init__.py` + numbered modules, one per heuristic family) so import resolution + ARCH-001/003 are exercised end-to-end (mirrors the examples-rust mini-crate).
- W0 CANARY: before freezing the catalog, prototype-scan pinned Aider (Apache-2.0) + chunkhound (MIT) at pinned commits, rank candidate rules by frequency x plausibility, and baseline against Ruff's PERF rule set (Perflint, MIT). Evidence discipline applied to the catalog itself, so M4 is not the first precision test (the M1 lesson: 5 rules caused 89% of the self-scan noise).

DESIGN BLIND SPOTS to resolve in W1 (from @oracle): comprehensions must be modelled as LoopNode with the iterable evaluated once (the Rust `for`-iterable fix, rust-backend.md 3.8) or most loop rules are blind or mis-depth; MODULE-LEVEL code needs a synthetic function record or script-style AI files (top-level loops) get ZERO findings; `.ipynb` notebooks must be decided explicitly (parse cells with line-offset mapping, or document the exclusion on the accepted-limitations page); ARCH-003 on Python is noisier than C (duck typing, ubiquitous names: get/save/run) -- expect Info/low and measure.

SCHEMA: MINOR 1.2 -> 1.3 widening `scan.languages` + `files[].language` to enum ["c","rust","python"] (6-7 hunks, same shape as the v1.1->v1.2 delta), new `docs/schema/metrics.schema.v1.3.json` + embedded byte-copy in src/schema/ + golden byte-copy + drift test; v1.2 retained as history; CLI VERSION_SUFFIX -> 1.3. rule_id pattern already open (no change). NOTE: tests/schema_1_2.rs currently ASSERTS v1.3 does NOT exist -- must flip.

Every finding's message must cite the CPython mechanism that causes the cost (catalog requirement: mechanism + fix + accepted FP class per entry).

Out of scope: bytecode/profiler analysis, cross-language linking (ADR-0004), C++/JS/TS backends (M6+), any release (M5, gated by ADR-0005), Windows/macOS-specific work.
