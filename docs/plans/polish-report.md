## Idea
Housekeeping and polishing program before the final launch, run as FIVE separate sessions (do not cram into one); H2 and H4 both touch `report.html` but are separate content and composition passes. Scope from the founder's six points plus the display-scaling finding, grounded in the M3 evidence:

(1) ATLAS PARITY — the M2 merge did not lose branch code: `feat/atlas-sim` never modified `atlas_brief.rs`. The branch report's seven blocks are `answer`, `actions`, `weight`, `blast`, `cards`, `noise`, `links`; main replaced them with the detail rail + four charts and moved the drills to separate pages. **H1 restores every branch block additively** — the one-sentence answer, the ranked-actions block with severity/confidence/why/trip/dedupe, the file cards, the noise/confidence disclosure (`files_without_functions`, `partial_parse_files`), the links/drills block, the inline drill content, and the full-width hero — while keeping main's rail and charts. Nothing branch-authored is dropped. **Founder decision (2026-10-27): the interactive story sim is included in the report**, so ADR-0012 Decision 5's companion-only stance is superseded by a new ADR; the report gains a fixed story script and inline story data (no fetch/HTTP server), with a static fallback. This is a forward composition change on main plus an explicit A12 amendment.

(2) 25-CAP RATIONALE — ratified D1 (`docs/specs/agent-report.md:27`, §3/§4): agent-report.md is a bounded skeleton (top 25 actions + top 25 profile rows) because an inline complete index reaches ~170k tokens on a 7.5k-finding scan; `agent-actions.json` carries the complete uncapped list (392/392 in the ConnectLocally run); every cap prints `N of M` and is named in `data_quality.caps`. **Decision (locked 2026-10-27): keep 25**; make the `N of M` disclosure and the full-list pointer unmissable; no cap flag, no schema change.

(3) ARTIFACT ROLES — do NOT blanket-merge. `metrics.json` is canonical; `agent-actions.json` is the complete machine action contract; `profile-queue.{md,html}` is the distinct KV3 function list; `report.{md,html}` is the narrative + Atlas; `agent-report.md` is the LLM digest. Real redundancies: report.md Appendix C re-renders all findings that `findings-detail` already owns; `findings-detail.md` duplicates `findings-detail.html` and the ranked-action rows in `agent-actions.json`; the MD/HTML pairs otherwise serve different consumers; `metrics.schema.v1.8.json` is a convenience copy. Decide per artifact via a role matrix (audience/consumer/uniqueness/action), then drop or link — never leave two full renderings of the same list.

(4) FORMATTING — unify typography, heading scale, escaping, table/link style and section ordering across report.md, agent-report.md, findings-detail.md, profile-queue.md and the HTML pages, using the Atlas warm-paper design as the visual reference. Markdown artifacts currently differ (escaped punctuation, heading levels, table conventions); HTML detail pages mirror report head/style while the Atlas page is a different design. Add a single style contract + shared render helpers so it cannot drift again.

(5) UNIQUENESS — every emitted file must have a named audience and consumer; produce the artifact matrix and delete/demote anything without one. Keep byte-determinism and the fixed output-contract §2 layout unless a deliberate contract change is approved.

(6) EXPLORER — `report.html#explorer` is legacy: `atlas_brief.rs:437` literally calls it "legacy static chart stems". It renders 8 linked figures + a top-10 component table + 11 component links + long caveat, all superseded by the Atlas map. **Decision (locked 2026-10-27): move it to a separate `explorer.html`** (linked once from the report footer); keep every chart on disk; the Atlas page stays answer-first. This is a visual change and must pass the founder vision gate (`@vision`) plus the deterministic/page-height budget.

(7) RESOLUTION & SCALE — the report is laid out for a fixed width: `SVG_W = 1400`, `PAGE_GRAPH_W = 868`, `#atlas-canvas{flex:0 0 868px;max-width:868px}`, `body{max-width:90rem}`, chart figures `max-width:1408px`, and 8–10 px type (`atlas_render.rs:42,46,127-128,155`; `mod.rs:1670`). All report output is vector (0 raster refs in `report.html`), so this is a **layout/legibility** defect, not blur: on a 3072×1920 display the page caps at 1440 px and the canvas at 868 px, so most of the screen is empty and type reads small at 100%. Policy: **responsive by default** (`width:100%` + preserved `viewBox`, fluid type via `clamp()`), plus an optional `--report-width <auto|1280|1440|1920|2560|3072>` render hint; **no scan-machine resolution auto-detection as the default** — a static report is opened later, possibly on another display (push-back recorded). Vector output stays DPR-independent; acceptance at 1280/1440/1920/2560/3072 and DPR 1/2, vision gate at 1440 and 3072.

Constraints: no schema bump unless the artifact contract change requires it (prefer none); **A12 is amended by a new ADR for the in-report story** (founder decision 2026-10-27): fixed story script, inline data, no fetch/HTTP, static fallback; byte-determinism preserved; full gate + story gate green; no push/tag without founder go. Measurements from the ConnectLocally run: 394 findings (13 hot), agent-actions 392 actions/651,958 B, findings-detail.md 347,970 B, findings-detail.html 408,612 B, report.md 21,607 B, report.html 128,388 B, profile-queue 395 functions.
