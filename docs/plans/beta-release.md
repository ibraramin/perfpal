## Idea
Produce Perfpal's first OFFICIAL proprietary BETA release: version 0.2.0-beta.1, containing the C AND Rust backends (Rust backend lands first via plan `rust-backend`, then this plan cuts the beta). Purpose: a real, distributable, presentable artifact the founder can show to entrepreneur/founder-fund programs — not a general-availability product (no public users intended). Research verdict (librarian, session 23) drives scope: DO binary hardening + checksums/signing + EULA + SBOM; SKIP deep obfuscation (the rustc-compatible LLVM obfuscator forks are unmaintained and legally murky, commercial Rust obfuscators do not exist, and obfuscation buys little — the real IP is the heuristic catalog, which stripping/signing cannot protect anyway) and SKIP license-key/activation at beta (PolyForm Strict + EULA is sufficient; revisit signed offline licenses at paid GA). Hardening: release profile opt-level=3, lto=\"fat\", codegen-units=1, strip=\"symbols\", panic=\"abort\", plus --remap-path-prefix to strip build-machine source paths from panic strings (note: rustc itself warns -Cstrip is NOT obfuscation). Integrity: SHA256SUMS (already produced) plus minisign-signed SHA256SUMS (minisign-verify MIT for verification), and GitHub artifact attestations via actions/attest-build-provenance (Sigstore/SLSA provenance; free for public repos, needs id-token:write + attestations:write) — the repo is source-available so public is acceptable; note the current repo is private (attestations on private need GitHub Enterprise Cloud), so decide public-vs-private for the beta tag deliberately. SBOM: cargo-sbom (MIT, SPDX 2.3 default) attached to the release, plus cargo-about (MIT/Apache-2.0) generating THIRD-PARTY-NOTICES (Apache-2.0 deps require attribution); cargo-deny allow-list already bans GPL-family (keep it as the enforcement gate). Legal: EULA derived from a standard template structure (license grant, restrictions on reverse-engineering/redistribution/commercial use, IP ownership, termination, warranty disclaimer, liability limitation, governing law, acceptance) bundled with the PolyForm Strict LICENSE; because binaries are not 'accepted' like source, surface the EULA + non-commercial notice in the release bundle and in --version/--help output. Platform signing: DEFER Windows Authenticode and macOS notarization at beta (Authenticode requires an HSM/token and $200-600/yr; Apple $99/yr); optionally add the cheap Azure Trusted Signing ($9.99/mo) if SmartScreen friction matters — otherwise document the unsigned-beta caveat. Distribution: publish as a clearly-labelled GitHub PRE-RELEASE (not latest GA) with the beta binaries, checksums, signatures, SBOM and EULA; feed the release asset list to the website milestone. Also add an examples-rust corpus. Dual review + full gates + tag discipline (the tag points at the commit whose workflow runs) before publishing; smoke-test the published musl binary end-to-end."

## Implementation
- B0 scope + version freeze: confirm 0.2.0-beta.1 semantics (prerelease of 0.2.0, C+Rust content), update Cargo.toml version, --version string, README beta banner, and CHANGELOG (move [Unreleased] into a 0.2.0-beta.1 section); record the beta's non-GA status explicitly (not for public/commercial use beyond evaluation).
- B1 release hardening: add the hardened [profile.release] (opt-level=3, lto="fat", codegen-units=1, strip="symbols", panic="abort") and --remap-path-prefix for build-machine paths; decide obfstr for any sensitive literals (cheap, MIT) and explicitly DOCUMENT that stripping is not obfuscation; verify the release binary still passes the published-artifact smoke test (exit 0, full report tree).
- B2 integrity + provenance: minisign-sign SHA256SUMS in release.yml (minisign, MIT) and add actions/attest-build-provenance (needs id-token:write + attestations:write) for SLSA/Sigstore provenance; decide and record repo visibility for the tag (attestations on private repos need GitHub Enterprise Cloud); keep in-CI sha256sum -c verification of every artifact.
- B3 SBOM + third-party notices: add cargo-sbom (MIT, SPDX 2.3) to CI producing an SBOM attached to the release, plus cargo-about (MIT/Apache-2.0) generating THIRD-PARTY-NOTICES; keep the cargo-deny GPL-family deny-list as the enforcement gate; ensure the SBOM confirms the no-copyleft closure.
- B4 legal: author the EULA from a standard template structure (grant, restrictions incl. no reverse-engineering/redistribution/commercial use, IP ownership, termination, disclaimer, liability cap, governing law, acceptance) bundled with the PolyForm Strict LICENSE; surface the EULA + non-commercial evaluation notice in the release bundle and in --version/--help; add a short privacy/telemetry statement (no telemetry).
- B5 code signing decision: DEFER Windows Authenticode + macOS notarization for the beta (cost/HSM friction) and document the unsigned-beta caveat in the release notes and README; optionally wire Azure Trusted Signing ($9.99/mo, best-smart-screen-reputation/cost ratio) if SmartScreen friction is judged material during beta testing; skip all deep-obfuscation and license-activation work (research verdict: no license-clean, viable options and not worth it at beta).
- B6 distribution + validation: publish as a GitHub PRE-RELEASE (not marked latest) with binaries, SHA256SUMS + minisign signature, SBOM, NOTICES, EULA and LICENSE; confirm tag discipline (the tag points at the commit running the workflow); smoke-test the published musl binary end-to-end against examples/ and examples-rust/; hand the release asset inventory + screenshots to the website milestone. Dual review (@reviewer + @requirements-reviewer) + fix wave, gates, then tag/publish.
