## Idea
Formalize and execute the session-34 founder direction: the path to Perfpal's first EVIDENCE-BACKED release, pitched as "Perfpal audits what AI wrote" (performance landmines in large AI-assisted codebases). HARD PUBLISH GATE: no release — including the code-complete v0.2.0-beta.1 — until (a) the benchmark suite is built AND run, and (b) an AI-code credibility showcase is verified. Sequence to first release: M1 Precision Gate (C+Rust) -> M2 Benchmark suite (build + RUN) -> M3 Python backend -> M4 AI-code showcase -> M5 First release. M6+ = JS -> TS -> C++ then cross-language linking (separate milestone AFTER the language sequence). Language order SUPERSEDES the prior C->Rust->C++->Python->JS->TS order to C -> Rust -> Python -> JS -> TS -> C++ (Python promoted, C++ demoted; data: AI-generated-code share arXiv 2603.27130 — Python 41.7%, JS 15.4%, C++ 7.8%, TS 7.8%, C 3.7%, Rust not top-8). JS and TS are separate milestones. Shipping = T0 (existing 6 unsigned binaries + minisign SHA256SUMS + SBOM + legal docs) + T2 packaging (winget portable, own Scoop bucket, own Homebrew tap, AUR -bin, cargo-binstall); T1 signing/notarization DEFERRED to GA. Evidence discipline = repro packet (pinned URL+commit+license, one-command scan, expected counts, determinism proof) + hand-verified true positives + accepted-limitations page; showcase only MIT/Apache-2.0/BSD repos. This plan's first step is the planning-only formalization (session 35): spec, plan, ADR-0003..0006, and the docs/roadmap.md rewrite. The existing beta-release plan (code complete B0-B6, publish parked) stays ACTIVE and becomes the M5 release node. No implementation code in the formalization step.

## Implementation
- Formalization baseline (planning-only, session 35): create spec `evidence-beta-spec` (repo scope); create this plan and link the spec; rewrite `docs/roadmap.md` replacing the `## Direction (PENDING FORMALIZATION)` block + stale M1-M3 sequence with formal M1-M6+ milestones; author ADR-0003 (language-order change), ADR-0004 (cross-language linking deferral), ADR-0005 (evidence/publish gate), ADR-0006 (T0+T2 shipping; T1 to GA); update CHANGELOG + state files. Zero implementation code.
- M1 — Precision Gate (C+Rust): triage and disposition the 5 noise rules that dominate the self-scan (~89% of 1219 findings on `perfpal src`: ALLOC-001 per-finding format!/to_string, ARCH-003 name-based `new` coupling, STR-001 Vec::push collision, MEM-002 clone copies, LOOP-008 member chains) — decide per rule whether to suppress, reframe (severity/confidence), or fix. Build a per-rule precision KPI harness (mutation/ground-truth fixtures) so precision is measured, not asserted. Regenerate goldens; dual review (@reviewer + @requirements-reviewer) then commit.
- M2 — Benchmark suite (build + RUN): construct the benchmark as ground-truth mutation fixtures + a scale ladder (small/medium/large corpora) + a determinism proof (byte-stable artifacts across runs). RUN it and record results as evidence in docs/evidence/. This step is a hard precondition for the publish gate; the metric is measured precision/recall against planted ground truth, not designed-on-paper.
- M3 — Python backend: add a Python scanner backend via the official tree-sitter-python grammar (MIT, exact pin per ADR-0001 G5), mirroring the full catalog with `PERF-PY-*` rule ids and honest reframing to Python idioms; schema MINOR bump admitting the "python" language token; add an examples-python corpus; keep the semantic-clang tier C-only. Dual review + gates before commit.
- M4 — AI-code credibility showcase: scan the flagship AI-authored repos — Aider (Apache-2.0, ~88% self-written) and chunkhound (MIT, 100% AI) — plus a famous human-written C/Rust repo for scale; hand-verify true positives; produce a repro packet per repo (pinned URL+commit+license, one-command scan, expected counts, determinism proof) and an accepted-limitations page. Showcase only MIT/Apache-2.0/BSD repos with minimal attributed spans. Verification of this showcase is a hard precondition for the publish gate.
- M5 — First release (un-parks `beta-release`): with M2 run and M4 verified, clear the residual beta blockers (EULA/privacy contact address + MINISIGN_SECRET_KEY/MINISIGN_PASSWORD secrets), publish `v0.2.0-beta.1` as a clearly-labelled GitHub pre-release (`--prerelease --latest=false`, never displacing v0.1.0 as Latest), and execute T2 packaging (winget portable, own Scoop bucket, own Homebrew tap macOS+Linux, AUR -bin, cargo-binstall). T1 signing/notarization stays deferred to GA. Tag discipline per the beta-release plan (tag points at the commit running the workflow).
- M6+ — Fast-follow reach (deferred, direction only): JS -> TS -> C++ backends as separate milestones, then cross-language linking as its own milestone AFTER the language sequence. Recorded here so scope does not creep into M1-M5; each becomes its own plan/session family when reached.
