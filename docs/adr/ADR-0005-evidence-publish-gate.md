# ADR-0005: Evidence-First Publish Gate — no release before benchmark + verified showcase

- **Status:** Accepted (founder direction recorded session 34; formalized 2026-09-25)
- **Date:** 2026-09-25
- **Deciders:** Founder + orchestrator (evidence: @librarian AI-code showcase feasibility, session 34; `docs/evidence/dogfood-rust-backend.md`)
- **Gates:** The `v0.2.0-beta.1` publish (plan `beta-release` B6) and every subsequent release claim.

## Context

`v0.2.0-beta.1` is **code complete** (plan `beta-release` B0–B6, commit `b3a1105`) but its publish was **parked** in session 34, before the tag. Two facts drove the hold:

1. **Precision is unproven at scale.** The Perfpal self-scan (`perfpal src` → 33 files, 1219 findings) is **~89% generated by 5 rules** and consists of documented accepted-FP/noise classes (`format!`/`to_string` ALLOC-001 volume, name-based ARCH-003 `new` coupling, `Vec::push` STR-001 collision, `.clone` MEM-002 copies, member-chain LOOP-008). There is no per-rule precision KPI; precision is asserted, not measured (`docs/evidence/dogfood-rust-backend.md`).
2. **Credibility collapses on a famous repo.** Publishing raw output on a large, well-known codebase invites a fatal "these findings are wrong" response. The founder's own framing: precision is existential for the pitch.

Session 34 also established the pitch: **"Perfpal audits what AI wrote."** A pitch about *verifiable* findings cannot ship on unverified ones. The prior "100%-AI-written C/Rust" story was dropped as unsubstantiable (no famous large mostly-AI-generated C/Rust OSS exists); the flagship AI-authored targets are Python (Aider ~88% self-written / Apache-2.0; chunkhound 100% AI / MIT), not C/Rust.

## Decision

**No release — including the code-complete `v0.2.0-beta.1` — until BOTH of the following hold:**

1. The **benchmark suite is built AND run** — ground-truth (mutation) fixtures + a scale ladder, with results recorded as evidence. "Built" alone is insufficient; it must be **RUN**.
2. An **AI-code credibility showcase is verified** — findings hand-checked on real AI-authored repos.

Supporting discipline (binding for any release claim):

- **Repro packet** per showcased result: pinned repo URL + commit + license, a one-command scan invocation, expected finding counts, and a determinism proof.
- **Hand-verified true positives**: claims rest on findings a human checked, not raw counts.
- **Accepted-limitations page**: an explicit, honest list of approximate/FP classes.
- **Showcase licensing**: only **MIT / Apache-2.0 / BSD** repos, with minimal attributed spans (copyright hygiene for a proprietary, acquisition-minded product).

## Rationale

1. **The pitch is a truth claim.** "Verifiable truth per finding" cannot coexist with unmeasured precision.
2. **Fame cuts both ways.** A famous repo makes the demo compelling *and* the failure mode catastrophic; the gate forces verification before exposure.
3. **Benchmark-then-release is asymmetric-safe.** The cost is a few sessions; the downside of a bad first impression on a flagship repo is irrecoverable for an acquisition-target narrative.
4. **It reframes the parked beta as sequenced, not stuck.** The beta is done; it simply waits at M5 for M2 (run) and M4 (verified).

## Alternatives Considered

- **Publish now, iterate in the open — rejected.** A noisy first release on a flagship repo would harden the "static analysis = noise" objection the product must beat.
- **Design-only benchmark (no run) — rejected.** A designed benchmark is a claim, not evidence; the gate names *run* explicitly.
- **Verify only on internal examples/ self-scan — rejected.** Internal corpora are self-selected; the showcase must be external, AI-authored, and permissively licensed.

## Consequences

**Positive**
- Every release claim is backed by run evidence + a hand-checked external showcase.
- The precision work (M1) is forced before exposure, where it is cheapest and safest.
- The M1→M5 sequence becomes self-justifying: each milestone produces the evidence the next gate consumes.

**Negative / mitigated**
- **The ready beta waits** through M1–M4 — mitigated by sequencing it as M5 (nothing is thrown away; `beta-release` stays active).
- **More work before any release** — accepted as the deliberate price of credibility.
- **FP/limitations advertising risk** (the accepted-limitations page may read as weakness) — mitigated by framing limitations as honesty (the product's differentiator), not as defects.

## Reversal Triggers

1. A precision KPI + benchmark run demonstrates that raw output on a flagship repo is already credible *without* a bespoke showcase.
2. External demand makes an earlier, clearly-labelled technical preview strictly more valuable than a verified one.
3. A license or attribution blocker removes every viable AI-authored showcase target (would require re-scoping the showcase, not dropping the gate).
