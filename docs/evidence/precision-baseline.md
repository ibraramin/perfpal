# M1 per-rule precision KPI — baseline evidence (plan `evidence-beta`)

> **Scope.** This is the **M1 lightweight per-rule KPI**: a labeled
> ground-truth (mutation) corpus plus a ratchet test that **measures**
> per-rule precision/recall with the REAL full pipeline. Precision becomes
> measured, not asserted. It is deliberately small and fast; it is **not**
> the M2 benchmark (see §5).
>
> **Reproduce:** `cargo test --test precision_kpi -- --nocapture`
> (add `--features semantic-clang` for the resolver build; both measure
> 1.0/1.0 — see §4).
>
> **Scope note.** The M1 *dispositions* (§1) ARE **production changes** —
> five Rust heuristic implementations, the shared `cross_file_call_edges`
> producer, and the registry/reporter catalog (Rust tier 23 → 22 rules).
> What THIS document's own change set adds is the labeled ground-truth
> corpus, the ratchet harness, and this evidence record.

## 1. M1 dispositions (the 5 noise rules)

The pre-M1 self-scan (`perfpal src`, 1219 findings) was ~89% generated by 5
Rust rules, all documented accepted-FP/noise classes. M1 disposed each one;
the harness in §2 locks the post-disposition behavior of **all nine M1 gate
rules** (the 5 Rust dispositions + their 4 C counterparts, with Rust
`PERF-RS-STR-001` kept as an always-silent retired control).

| # | Rule | Disposition | Where |
|---|------|-------------|-------|
| 1 | `PERF-RS-ALLOC-001` | **Aggregate** — one finding per **innermost enclosing loop** (not per call site), plus **literal-receiver suppression** (`"x".to_string()` / `"x".to_owned()`). | `src/analyzer/heuristics/rust/alloc.rs` |
| 2 | `PERF-RS-ARCH-003` | **Uniqueness gate** — the name-based fallback emits an edge only when the language-scoped definition set contains **exactly one** file; zero (undefined) or many (ambiguous, e.g. `new`) emit nothing. | `src/analyzer/heuristics/rust/arch.rs` + shared `cross_file_call_edges` |
| 3 | `PERF-RS-MEM-002` | **Family narrowing** — `clone` / `to_vec` removed from the block-copy family (borrow-checker clones and `Copy` bit-copies are not block copies; re-admission needs receiver-type evidence). | `src/analyzer/heuristics/rust/mem.rs` |
| 4 | `PERF-RS-LOOP-008` | **Subscript requirement** — a chain must contain at least one `Subscript` element; pure member chains (`ctx.ops.fun`) no longer fire. | `src/analyzer/heuristics/rust/loop.rs` |
| 5 | `PERF-RS-STR-001` | **Retired for Rust** — the C `strcat` O(n²) premise does not transfer to amortized `push`/`push_str`, and the rule's real effect was the `Vec::push` name collision. The Rust tier is now 22 rules. | `src/analyzer/heuristics/rust/str.rs` (no emitter) |

The C counterparts (`PERF-C-ALLOC-001`, `-ARCH-003`, `-MEM-002`, `-LOOP-008`,
`-STR-001`) are unchanged by M1 and are included in the same ratchet so the
gate covers the whole C+Rust M1 surface.

## 2. Harness usage

```bash
# default build
cargo test --locked --test precision_kpi -- --nocapture

# semantic-resolver build (libclang present or gracefully absent)
cargo test --locked --features semantic-clang --test precision_kpi -- --nocapture
```

What the harness (`tests/precision_kpi.rs::precision_kpi_meets_baseline`) does:

1. Runs the **real** pipeline via `cli::run_with` (scan → analyze → aggregator
   → writer) over the committed corpus `tests/fixtures/precision/`. The corpus
   is scanned **in place and stays read-only**; `metrics.json` is written to a
   fresh tempdir outside it.
2. Joins `metrics.json` findings to `tests/fixtures/precision/labels.json` by
   `(rule_id, path, span.start_line)`.
3. Computes, per in-scope rule:
   - **TP** = `fire` labels matched by a finding;
   - **FN** = `fire` labels with no matching finding;
   - **FP** = findings of that rule matching **no** `fire` label (this
     subsumes every finding on a `silent` (rule, path));
   - `precision = TP/(TP+FP)` (1.0 when `TP+FP==0`);
     `recall = TP/(TP+FN)` (1.0 when `TP+FN==0`).
4. Asserts `precision >= baseline.precision` **and**
   `recall >= baseline.recall` for every rule, printing the exact mismatches
   and a markdown table under `--nocapture`.

### Corpus layout (`tests/fixtures/precision/`)

Each rule has a planted **true positive** and a **silent control** (near-miss
that must stay silent). Inline comments name the intended rule/disposition;
`labels.json` is the authoritative coordinate manifest and carries the
intended **1.0/1.0** baseline.

| Rule | True positive (fires) | Silent control (stays silent) |
|------|-----------------------|-------------------------------|
| `PERF-RS-ALLOC-001` | `rust/alloc.rs` — `Vec::new()` in an innermost loop (finding anchors at the loop span) | `rust/alloc_silent.rs` — out-of-loop `Vec::new()`, and literal-receiver `"x".to_string()` in a loop |
| `PERF-RS-ARCH-003` | `rust/arch.rs` — call to `compute_total`, defined in exactly one other file | `rust/arch_silent.rs` — call to `new`, defined in two files (ambiguous) |
| `PERF-RS-MEM-002` | `rust/mem.rs` — `copy_from_slice` in an innermost loop | `rust/mem_silent.rs` — `clone()` in a loop and a block copy outside any loop |
| `PERF-RS-LOOP-008` | `rust/loop_chain.rs` — indexed chain `row.cells[i].value` (depth 3, has a `Subscript`) in an innermost loop | `rust/loop_silent.rs` — pure member chain `top.mid.leaf.value` (depth 3, no subscript) |
| `PERF-RS-STR-001` | — (retired; no emitter) | `rust/alloc_silent.rs` — `Vec::push` in a loop |
| `PERF-C-ALLOC-001` | `c/alloc.c` — `malloc` inside a loop | `c/alloc_silent.c` — `malloc` outside any loop |
| `PERF-C-ARCH-003` | `c/arch.c` — call to `compute_total`, defined in exactly one other file | `c/arch_silent.c` — call to same-named **file-local** `new` defined in two files (ambiguous at the syntactic uniqueness gate; internal linkage keeps it unresolved at the semantic tier too) |
| `PERF-C-MEM-002` | `c/mem.c` — `memcpy(dst, src, len)` (non-literal size) in a loop | `c/mem_silent.c` — `memcpy(dst, src, 8)` (literal size) in a loop |
| `PERF-C-LOOP-008` | `c/loop.c` — `top->mid.leaf.value` (depth 3) in an innermost loop | `c/loop_silent.c` — `mid->leaf.value` (depth 2) |
| `PERF-C-STR-001` | `c/str.c` — `strcat(dst, src)` into an identifier destination in a loop | `c/str_silent.c` — `strcat` outside any loop |

`PERF-RS-STR-001` is the retired rule: 0 TP / 0 FP / 0 FN ⇒ 1.0/1.0 by the
zero-denominator convention (it has no emitter, so there is nothing to miss).

Findings **not** in the table (7 of the 16 on this corpus) belong to
out-of-scope rules and are deliberately excluded from the KPI.

> **Honesty rule.** The baseline in `labels.json` is the **intended**
> 1.0/1.0 target. A measured shortfall is **never** fixed by lowering the
> baseline: it is either a corpus/label bug (fix the fixture) or a **real
> analyzer gap** (stop and report). The ratchet exists to make precision
> measured, not asserted.

The self-scan is a *production* run over the real source tree; the §3 corpus

The harness measures the **same** 1.0/1.0 in both build configurations:

  definitions remain genuinely ambiguous at both tiers, so the
  `ARCH-003` silent control stays silent and the TP still fires. No
  production `src/` change is needed to make the two builds agree on this
  corpus.

## 5. M1 KPI vs M2 benchmark

This document is the **M1 lightweight per-rule KPI only**. It is
deliberately:

- **small** — one planted TP + one silent control per rule, hand-labeled;
- **fast** — a single real-pipeline run over a 22-file corpus;
- **per-rule** — precision/recall for each of the 9 M1 gate rules.

**M2 builds the full benchmark** on top of this: a **scale ladder**
(small/medium/large corpora) with **measured precision/recall against planted
ground truth**, and a **determinism proof** (byte-stable artifacts across
runs), recorded as evidence and **RUN** before the publish gate. M1 makes
precision measured; M2 makes it measured *at scale and reproducibly*.

## 6. Known limitations recorded by M1 review

- **Semantic-tier USR ambiguity (C-only; deferred).** With
  `--features semantic-clang`, `build_definition_map` keys on libclang USRs,
  which are **location-independent for external-linkage** functions: two
  non-`static` same-named definitions in different TUs share a USR (e.g.
  `c:@F@new`), so the resolved branch can select one and emit an edge that the
  syntactic uniqueness gate would suppress. Blast radius is limited to
  link-invalid C (duplicate external definitions); the **default build and the
  entire Rust tier are unaffected**, so the M1 Rust self-scan result is
  unchanged. Hardening candidate (M2 / semantic tier): reject a resolved site
  whose USR maps to more than one defining file. For this reason the corpus's C
  `ARCH-003` silent control uses **file-local `static`** definitions, which are
  genuinely ambiguous at both tiers.
- **`PERF-RS-LOOP-008` does not model pointer dereference.** The gate is
  `Subscript`-based; a pure deref chain (`(*p).a.b.c`) is `MemberAccess`-only
  and stays **silent** (see the LOOP-008 entry in
  `docs/heuristics/rust-catalog.md`). An accepted false negative, recorded
  rather than papered over.
